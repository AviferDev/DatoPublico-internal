# Specs de feature

Un fichero por feature: `docs/specs/<feature-id>.md`.

- Los produce la skill `feature-spec` (rol `planner`).
- Deben ser operativos: objetivo, no-objetivos, escenarios de aceptación,
  investigación del repo, enfoque técnico, cambios de ficheros esperados,
  impacto en documentación durable, plan de verificación, evidencia y checklist
  del validador.
- Anotan el `ft_id` (y `pt_id` si la feature se divide) en su cabecera.
- Objetivo de tamaño: 100–250 líneas.

Convención de `<feature-id>`: el `id` de la entrada en `feature_list.json`
(p. ej. `bootstrap-monorepo-gradle` → `docs/specs/bootstrap-monorepo-gradle.md`).
